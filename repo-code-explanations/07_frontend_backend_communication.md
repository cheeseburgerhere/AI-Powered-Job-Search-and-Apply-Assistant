# Chapter 7: Frontend-Backend Communication

In [Chapter 6: Zustand State Management](06_zustand_state_management__frontend_stores__.md), we learned how the frontend remembers your data while the app is running. But where does that data actually come from? Since our AI Assistant uses powerful Python libraries, it needs a real computer "brain" (the Backend) to do the heavy lifting.

### The Application Architecture
In this branch, the `ai-job-assistant` uses a standard web application architecture that separates the React frontend and the FastAPI backend. These two parts run concurrently and communicate seamlessly.

### Key Concept 1: The API Client
The frontend uses the `axios` library to communicate with the backend. It relies on a standard API route path so it doesn't have to keep track of dynamic port numbers.

In `frontend/src/api/client.ts`, you see:
```typescript
import axios from 'axios'

const api = axios.create({
  baseURL: '/api',
  headers: { 'Content-Type': 'application/json' },
})

export default api
```
Because `baseURL` is set to `/api`, any requests to `api.get('/jobs')` are automatically routed to our backend API endpoints.

### Key Concept 2: The Vite Proxy (Development)
When developing the app locally, Vite acts as the intermediary. Running `npm run dev` starts the React app on port 5173. But how does it reach the backend on port 8000?

In `frontend/vite.config.ts`, there is a proxy configuration:
```typescript
export default defineConfig({
  plugins: [react(), tailwindcss()],
  server: {
    proxy: {
      '/api': 'http://localhost:8000',
    },
  },
})
```
This tells Vite: "If the frontend asks for anything starting with `/api`, forward it directly to `localhost:8000` (where our Python FastAPI backend lives)!"

### Key Concept 3: Docker Orchestration
When running the full stack, we use Docker Compose to manage both services simultaneously.
In `docker-compose.yml`, you'll see two primary services defined:
1. `backend`: Starts the Python FastAPI server on port 8000
2. `frontend`: Starts the Vite development server on port 5173

Docker handles networking between these containers internally. The `depends_on: - backend` instruction ensures the backend starts up before the frontend tries to communicate with it. 

### Summary
In this chapter, we learned how the React frontend connects with the Python backend in our architecture. We rely on standard HTTP requests directed to `/api`, which are seamlessly routed to the Python `uvicorn` instance using Vite's proxy during local development or standard container network routing via Docker in production.
